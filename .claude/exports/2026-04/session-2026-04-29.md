## 一、设计阶段

### 1.1 项目启动

用户提供了 `application.md` 作为项目起点，包含业务背景、目标与非目标定义。同时提出 7 点核心思考方向：

1. **Harness Engineering** — 利用 `.claude/` 目录体系管理 Agent 行为
2. **文件归档** — 设计文档、沟通记录的结构化存储
3. **.claude 目录** — prompts、rules、skills、exports 的分层组织
4. **跨页面意图识别** — AI 助手在不同页面间理解用户意图的能力
5. **写操作回滚** — 对账目等写操作的安全保障机制
6. **记忆能力** — AI 助手的多层次记忆系统
7. **技术栈** — Go 后端 + Vue3 前端 + 向量数据库

### 1.2 核心决策沟通（逐一记录）

| 2 | 跨页面意图识别 | B 方案 | 回答 + 跳转建议，不强制跳转 |
| 3 | 记忆系统层次 | C 方案 | 四层架构：画像 + 事实 + 情景 + 对话 |

### 1.3 深度讨论

#### 1.3.1 统计分析与预测能力

用户追问需要支持的分析能力：
- 同比环比分析
- 预算合理性评估
- 消费预测
- 行为预测
- 提醒功能

AI 分析了 5 大分析能力矩阵，提出实现策略：Skill 化分析 + 预计算缓存。用户确认方向一致。

#### 1.3.2 意图识别 A+ 方案

**演进过程：**

- **初始方案 A：** LLM 原生识别 + 页面感知 + 置信度分级
- **用户追问：** 是否有隐藏问题？
- **AI 自审发现 4 个隐患：**
  1. 全量 Skill 摘要传递效率问题
  2. 置信度不可验证
  3. 缺少业务规则兜底
  4. 幻觉风险未充分防御
- **A+ 改进方案：** 全量 Skill 摘要一轮完成、置信度可验证、业务规则兜底
- **用户要求杜绝幻觉 →** AI 设计五层反幻觉防线 + `data_ref` 结构化引用

**五层反幻觉防线：**
1. Skill 约束层 — 限定可调用的数据源
2. Tool 校验层 — 返回数据结构化验证
3. 引用追踪层 — `data_ref` 标记每条数据来源
4. 输出校验层 — 数值交叉验证
5. 用户确认层 — 关键操作二次确认

#### 1.3.3 ReAct 机制

- 用户确认需要轻量 ReAct，但要求不能降低响应速度
- AI 设计：LLM 输出结构驱动判定，5 种路径：
  1. 直接回答（无需工具调用）
  2. 单次工具调用
  3. 多步工具链
  4. 澄清追问
  5. 拒绝执行
- 不无脑 ReAct，按需触发
- 用户担心流式反馈不稳定 → AI 改为"预估时间 + 骨架屏为主，步骤通知为辅"

#### 1.3.4 会话连续性

- 用户追问：页面切换是否中断对话？
- AI 设计方案：Session 与页面解耦，任务绑定 `page_context` 快照
- 切换页面时保留对话上下文，仅更新页面感知信息

## 二、实施阶段

### 2.1 阶段规划

| 阶段 | 内容 | 依赖 |

| P1 | 基础设施 + Auth + Biz Mock | 无 |

### 2.2 P1: 基础设施 + Auth + Biz Mock

**任务数：** 10 个 Task，初始用 subagent 执行。

**遇到的问题及解决：**

1. **沙箱权限问题** — `go get` 无法写入模块缓存，用户手动执行依赖安装
2. **Go 版本冲突** — 1.22 vs 1.23，用户确认统一用 1.22
3. **配置方式改造** — 用户要求支持 `config.yaml` 配置 → 改造为 YAML + 环境变量 + 默认值三级配置

**代码质量评估：** 发现 4 Critical + 7 Important，全部修复。

### 2.3 P2: Memory Manager

**任务数：** 6 个 Task

**任务链路：** 数据模型 → DAO → Embedding + Milvus → 对话历史 → MemoryStore/Retriever → 验证

**关键设计决策：**
- L2（事实记忆）：同步 Embedding，写入时立即向量化
- L3（情景记忆）：异步 Embedding，后台队列处理
- 三级降级策略：Milvus 不可用 → Redis 缓存 → MySQL 全文检索

### 2.4 P3: Skill Manager

**任务数：** 4 个 Task

**任务链路：** 数据模型 → Registry → 热更新 → 内置 Skill YAML

**关键修复：** 用户要求并发安全改为值拷贝返回 → 已修复

**产出：** 7 个内置 Skill YAML 文件，覆盖全部 6 个页面。

### 2.5 P4: AI Engine（核心）

**任务数：** 5 个 Task

**任务链路：** LLM 抽象层 → Engine 核心 → Tool 实现 → Connection Manager → 对话 API

**核心能力：**
- ReAct 循环引擎
- 反幻觉校验管线
- WebSocket 连接管理（含心跳、重连、降级）

### 2.6 P5: Analytics + Operation Logger

**任务数：** 3 个 Task

**任务链路：** OpLog → Analytics Engine → Tool 注册

**产出：** 9 个 AI Tool 注册完成，覆盖记账、查询、统计、预测等场景。

### 2.7 P6: 前端 Vue3 Web Demo

**任务数：** 5 个 Task

**任务链路：** 项目初始化 → 三栏布局 → 认证 + API → 对话窗口 → 动态面板 + 图表

**前端能力：**
- 登录/注册页面
- 三栏布局（导航 + 对话 + 动态面板）
- 对话窗口（WebSocket 实时通信 + HTTP 降级）

### 3.3 跨阶段联动检查

7 条链路全部通过：

1. **AI Engine → Biz Service 调用链** — Tool 调用业务服务，参数传递正确

## 五、关键经验总结

### 5.1 设计阶段

- **第一性原理驱动决策** — 每个决策都经过 2~3 个方案对比，用户基于本质需求选择
- **AI 自审机制有效** — 自审发现的 7 个问题和意图识别 4 个隐患，避免了实施阶段返工
- **反幻觉是核心挑战** — 记账场景对数据准确性要求极高，五层防线设计是必要的

### 5.2 实施阶段

- **环境问题不可忽视** — 沙箱权限、Go 版本冲突等环境问题需要提前识别
- **分阶段实施 + 逐阶段验收** — 有效控制了质量风险
- **Critical 问题集中在安全和稳定性** — JWT、密码处理、goroutine 泄漏、panic 防护

### 5.3 质量保障

- **累计修复 27 个问题**（9 Critical + 13 Important + 5 Minor）
- **跨阶段联动检查** 是发现集成问题的关键手段
- **三轮验收** 确保了最终交付质量
