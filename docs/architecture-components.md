## 关键时序：记账场景（单步直达）

```
用户 → "午饭30元"
  │
  ├─ [0ms] SSE 连接建立
  ├─ [0ms] thinking: "正在理解你的意图..."
  ├─ [30-210ms] preloadContext (并行: L1+L2+L3 || L4 || L5)
  ├─ [~5s] LLM ChatSync (意图识别 + Tool Call)
  ├─ [~13ms] Tool 执行: create_bill
  ├─ [0ms] 写操作快速返回 (跳过第二次 LLM)
  └─ [0ms] done 事件
  
  总耗时: ~5.2s
```

## 关键时序：查询场景

```
用户 → "今天花了多少"
  │
  ├─ [0ms] thinking: "正在理解你的意图..."
  ├─ [30-210ms] preloadContext
  ├─ [~5s] LLM ChatSync (意图识别 + Tool Call)
  ├─ [~13ms] Tool 执行: get_total_spent
  ├─ [0ms] 查询快速返回 (跳过第二次 LLM)
  └─ [0ms] done 事件
  
  总耗时: ~5.2s
```

## 关键时序：闲聊场景（真流式）

```
用户 → "你好"
  │
  ├─ [0ms] thinking: "正在理解你的意图..."
  ├─ [30-210ms] preloadContext
  ├─ [~800ms] LLM Stream 首 token (thinking 内容)
  ├─ [~1.3s] </think> 后首个 chunk 推送
  ├─ [持续] chunk 事件逐步推送
  └─ done 事件
  
  首字: ~1.3s
```

## 容量估算

| 资源 | 配置 | 支撑能力 |
|------|------|---------|
| MySQL 连接池 | max_open=100 | 100 路并发查询 |
| Redis | 单实例 256MB | 10000+ session 历史 |
| Milvus | IVF_FLAT, 1024-dim | 百万级向量检索 |
| LLM 信号量 | max_concurrent=20 | 20 路同时调用 LLM |
| Goroutine | 无硬限制 | 依赖信号量背压 |

## 故障预案

| 故障 | 影响 | 恢复策略 |
|------|------|---------|
| MiniMax API 超时 | 单次对话失败 | 返回降级响应，不存入历史 |
| Milvus 不可用 | L2/L3 记忆检索降级 | 回退到 MySQL 关键词搜索 |
| Redis 不可用 | 对话历史丢失 | 跳过历史加载，功能不受影响 |
| MySQL 不可用 | 全部功能不可用 | 健康检查失败，服务标记不健康 |
| LLM 信号量满 | 请求排队等待 | ctx 超时后返回降级响应 |

## 多租户隔离

- MySQL: 所有 DAO 查询强制 `WHERE user_id = ?`
- Redis: key 命名空间 `session:{user_id}:{session_id}`
- Milvus: 搜索过滤 `user_id == {user_id}`
- PendingStore: key = `{user_id}:{session_id}`
- WebSocket: 连接绑定 user_id，JWT 认证
