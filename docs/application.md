# 咔皮记账App 内嵌式AI助手 - 业务&目标说明
## 一、业务背景
我们正在为「咔皮记账」App 构建全场景内嵌式 AI 助手。该助手会出现在 App 的每一个核心页面（首页、记一笔、账单详情、预算、报表、资产管理等），用户可以随时唤起，与助手就当前页面的核心功能进行对话式交互。

典型交互场景示例：
1. 在「记一笔」页面：用户说"昨天星巴克 38 元"，助手直接帮他完成结构化录入；
2. 在「账单详情」页面：用户问"这个月外卖花了多少？比上月多吗？"，助手基于当前账本数据回答；
3. 在「预算」页面：用户说"帮我把娱乐预算调到 800"，助手完成预算修改并解释变化；
4. 在「资产」页面：用户问"我现在能不能买这个 5000 元的相机？"，助手综合负债、预算、现金流给出建议。

我们希望这套助手具备 SOTA（State-Of-The-Art）智能体验：能够调用工具、调取用户上下文、复用历史记忆、按页面动态加载技能（Skills），并在 5 秒以内给出首字响应。

## 二、目标（In-Scope）
设计并实现一套线上多并发 AI 助手服务，核心能力要求如下：
- 支持 30~100 路并发会话（持续对话，长连接 / 流式输出）；
- 性能指标：单次对话首字延迟 P95 ≤ 5s，端到端工具调用回合 P95 ≤ 12s；
- 记忆能力：每用户独立的持久化 Memory（人物画像、偏好、历史关键事实）；
- 技能扩展：基于 Claude Skills 的能力扩展机制，业务侧可独立迭代/发布 Skill，无需重启服务；
- 页面感知：page-aware 设计，根据请求来源页面动态选择、裁剪可用 Skill 与工具集；
- 多租户隔离：不同用户的 Memory、Session、Skill 权限严格隔离。

交付要求：
1. 提供可运行原型（prototype），打通2~3个真实页面场景端到端Demo；
2. 输出完整可复盘架构设计文档，包含组件图、关键时序图、容量估算、故障预案。

## 三、非目标（Out-of-Scope）
1. 无需实现完整咔皮记账业务后端，账单、预算、资产等接口可通过 Mock 方式实现；
2. 无需进行模型自训练、微调等定制化模型优化工作；
3. 无需搭建生产级全套监控告警体系，仅需输出监控设计思路与核心指标；
4. 无需开发 App 端完整UI，最小化 Web / CLI 客户端即可满足演示需求。
